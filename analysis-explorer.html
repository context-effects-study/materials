How the registered analysis reaches a conclusion for each model

Before collecting any data, we ran the analysis code on simulated people and on 15 simulated models, each built to behave in one known way. Choose a model and press Play. The page shows the five steps of the Analysis Plan in order, with the numbers the code wrote for that model, and ends at the scenario the code assigned to it.

The page reaches no result of its own. Every class, test result and scenario is read from analysis/results_pack/, which analysis/analyze.py writes, every cutoff from analysis/registered_constants.py, and what each model was built to show from analysis/synth.py. The simulated people make 1,400 choices per cell, more than the planned 350 to 700, so that each planted pattern is clear: the run checks which branch of the decision tree the code takes for each pattern. How often a test reaches a conclusion at the planned sizes is reported in Web Appendix E (Table WA-E4); at those sizes we do not expect a conclusion of no difference on the memorization, argument-strength and trajectory tests.

Space plays or pauses; the arrow keys move between steps.
